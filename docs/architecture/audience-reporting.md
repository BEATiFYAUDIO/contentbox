# AUDIENCE Checkpoint B: reporting API

`GET /audience/summary` remains authenticated and scoped to the creator's non-deleted works. Optional `range` is `7d`, `30d`, `90d`, or `all` (default). Optional `page` is 1–1000; each page contains at most 50 works. Invalid parameters return HTTP 400 with `INVALID_AUDIENCE_QUERY`.

The dated ranges mean UTC calendar days including today, from 00:00 UTC on the first day through the request time (exclusive). `all` means all available history for legacy opens and paid purchases, while new Buy-page views are limited to their 395-day retention window. Dated ranges have daily buckets; `all` has monthly buckets only for the last 395 days. Periods are chronological. A period with no observed new-view coverage has `views: null` and `viewCoverage: "unknown"`; a partially covered period is marked `partial`. Zero means an observed period with no recorded views.

The response retains `totalViews`, `totalLegacyOpens`, `totalPurchases`, `conversionRate`, and `items`. It adds `range`, `series`, `pagination`, `undatedPaidPurchases`, per-work `rank` and `series`, and `metadata` with UTC boundaries, definitions, retention, coverage, and bucket granularity. Per-work rank is descending new views, then descending paid purchases, then ascending content ID. Paging does not change account totals. No buyer identity or payment amount is returned.

New views use `AudienceEvent.createdAt` and `definition=buy_page_v2`. Legacy opens remain separate and untouched. Completed purchases are `PaymentIntent` records with `purpose=CONTENT_PURCHASE` and `status=paid`. Dated counts and trends use `paidAt`; the all-time count also includes paid intents without `paidAt`, exposed as `undatedPaidPurchases`. Pending, failed, expired, and other-purpose intents are excluded.

`earliestAvailableBuyPageViewAt` is the first retained/available new-view event for this creator. It is **not** a known tracking-activation time; `trackingActivationAt` remains null. `coverageFrom` is the later of this observed boundary and the retention cutoff. A period before that boundary is unknown or incomplete, not silently zero. The view-to-purchase ratio uses only dated paid intents from the comparable retained-view window, divided by recorded new views. It is a ratio of aggregate counts, not unique-visitor or verified-buyer funnel conversion. If there are no recorded views, conversion is null. Monthly/daily buckets crossing the coverage boundary have null conversion. Older paid purchases stay in the all-time paid count but do not inflate conversion.

Queries aggregate counts in SQLite, use the existing audience and content/payment indexes, return no raw event or buyer rows, and paginate per-work results. The only commerce reads are counts of paid intents; checkout, receipts, access, and settlement code and schema are unchanged. The API is intended for local Core reporting; the dashboard is unchanged in Checkpoint B.
